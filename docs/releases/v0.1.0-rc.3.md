# Endure v0.1.0-rc.3 prerelease notes

This candidate is an experimental Bittensor testnet-alpha release. Mainnet
serving remains prohibited in code.

- Package/API version: `0.1.0rc3`
- Git tag after live acceptance: `v0.1.0-rc.3`
- Protocol key: `30` (unchanged — no watched protocol path differs from
  `v0.1.0-rc.2`; wire formats, resolved values, scoring math, and
  aggregation are identical)
- Bittensor testnet netuid: `504`
- Public API: `https://api.testnet.endure.network`

The candidate hardens operational surfaces observed during the rc.2 soak
and closes the review follow-ups that need no protocol change:

- `/health` grants the overdue classifier a one-worst-case-tick grace
  (1800s) past each horizon's due time, so the scheduled soak probe no
  longer reads a healthy midnight catch-up as degraded/503; genuinely
  missed windows still degrade.
- The miner watchdog exit arms the same bounded hard-exit fallback as the
  validator: a wedged non-daemon thread can no longer hold the process in
  teardown forever and starve the supervisor of a restart.
- The JSON console formatter's ASCII/bidi-escaping defense is pinned by a
  regression test, and the unreachable-collector drain test no longer
  races port reuse.

Known limitations are maintained in
[`../economic-limitations.md`](../economic-limitations.md). In particular,
duplicate/Sybil resistance and independent-validator quorum are unresolved.
Only one public validator endpoint currently exists.

Deployment identity for the soak probe: set `SOAK_EXPECTED_SHA` to the
promotion merge commit at deploy time; `SOAK_EXPECTED_PROTOCOL_KEY` stays
`30`. The probe reads red for up to ten minutes after any restart by
design.

This range adds no database migration (schema head remains `0015`) and no
protocol key change, so rollback is an image-only, lockstep rollback of
both services to the recorded `v0.1.0-rc.2` staging deployment with no
commit-window constraint: both builds speak identical key-30 wire formats.
