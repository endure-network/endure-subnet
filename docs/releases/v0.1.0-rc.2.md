# Endure v0.1.0-rc.2 prerelease notes

This candidate is an experimental Bittensor testnet-alpha release. Mainnet
serving remains prohibited in code.

- Package/API version: `0.1.0rc2`
- Git tag after live acceptance: `v0.1.0-rc.2`
- Protocol key: `30`
- Bittensor testnet netuid: `504`
- Public API: `https://api.testnet.endure.network`

The candidate makes the validator's archive-heavy horizon resolution
watchdog-safe: target resolution is bounded by a per-tick wall-clock budget
and a shared deadline enforced down to individual archive requests, deferring
remaining work to the next tick through the persisted `partially_scored`
resumption path instead of restarting nightly. Deadline exhaustion can never
void a resolvable coordinate. Wire formats, resolved values, scoring math,
and aggregation are unchanged from key `29`.

It also hardens watchdog exit paths (guaranteed process restart even when
teardown itself fails), classifies miner push transport failures separately
from validator rejections, surfaces process start/uptime through `/health`
so the soak probe flags restarts, and adds opt-in operator log shipping
(RFC 5424 syslog drain and JSON console output, both off by default).

Known limitations are maintained in
[`../economic-limitations.md`](../economic-limitations.md). In particular,
duplicate/Sybil resistance and independent-validator quorum are unresolved.
Only one public validator endpoint currently exists.

Deployment identity for the soak probe: set `SOAK_EXPECTED_SHA` to the
promotion merge commit and `SOAK_EXPECTED_PROTOCOL_KEY` to `30` at deploy
time; the probe requires both and reads red for up to ten minutes after any
restart by design.

This range adds no database migration (schema head remains `0015`), so
rollback is an image-only, lockstep rollback of both services to the recorded
key-29 staging deployment. Roll back before the first key-30 commit window;
after it, submissions recorded under key 30 are rejected by a key-29
validator and the round must be allowed to close before re-promotion.
