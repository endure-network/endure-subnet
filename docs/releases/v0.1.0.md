# Endure v0.1.0

Initial Alpha Risk release, with experimental economics and explicit operator
acknowledgement for mainnet serving.

- Package/API version: `0.1.0`
- Release tag: `v0.1.0`
- Protocol key: `2041`; unchanged by final release preparation
- Images: `ghcr.io/endure-network/endure-subnet-validator` and
  `ghcr.io/endure-network/endure-subnet-miner`, Linux/amd64
- Channels: `:testnet` for qualified staging candidates; `:prod` and `:v0.1.0`
  for this release. Deploy by digest to pin exact image bytes.

## Owner release decision — 2026-09-20

The owner accepted the accumulated staging run as sufficient for the initial
image publication and authorized publishing while staging continues. The
recent operator tooling and publication changes, followed by final version
metadata, do not require a fresh seven-day soak for this release.

This is an explicit exception to the default unchanged-revision soak rule.
The economic and independent-validator limitations described in
[economic limitations](../economic-limitations.md) remain disclosed and are
accepted for initial publication, not represented as resolved. CI and localnet
qualification remain required for the selected staging source commit.

Publishing images does not deploy the Endure-operated services on mainnet or
move wallets or funds. Each operator chooses deployment timing and must use
the matching [serving-stage acknowledgement](../running_on_mainnet.md).

## Changes since rc.3

- Signed commit/reveal fields, bounded reveal persistence, and idempotent
  accepted retries under protocol key `2041`.
- A 15-subnet Alpha Risk universe, active-coordinate payout and consensus,
  and retained reputation for retired targets.
- Independent validator and miner container installation; the optional
  combined deployment accepts tags or digests and retains previous image IDs
  for rollback.
- Testnet and production channels reuse published candidate digests.

## Publication and rollback

Promote `develop` to `staging`, then `staging` to `main`, using merge commits.
Tag the qualified staging source commit reachable from `main`, because its
`sha-<commit>` images are the inputs to production publication. The production
workflow adds `:prod` and `:v0.1.0` to those recorded image manifests without
rebuilding. Record both resulting digests in the GitHub release.

Coolify currently builds separately from the same source. Source identity and
runtime content checks do not prove that its image digest equals the published
image digest; this release does not claim that equivalence.

Final version preparation changes no schema, protocol key, or scoring behavior.
Retain the previous key-2041 image references and database backup. Follow the
[operator rollback procedure](../deploy/operator-node.md#rollback); reverting
to a key-30 candidate requires a separate protocol compatibility decision.
